# Translations (i18n)

Tabitat ships in English only, but every user-visible string is a message in
`public/_locales/en/messages.json` (Chrome's `_locales` format), so adding a language needs no
code change.

## Where strings come from

- UI: `t("key", subs?)` and `plural(n, "oneKey", "manyKey")` from `src/i18n`. Keys are typed
  from the en file, so a missing key fails `npm run typecheck`.
- Manifest and Web Store listing: `__MSG_key__` in `wxt.config.ts` (`appName`,
  `appNameNewTab`, `appDescription`, `actionTitle`, `cmd*` for the keyboard shortcuts).
  Chrome shows these on the extensions page, the toolbar and the shortcuts page.
- Worker: the HTML export labels (`EXPORT_LABEL_KEYS` in `src/background/handlers.ts`) go
  through `chrome.i18n.getMessage`.
- The suspended placeholder page reads `chrome.i18n` directly (no UI bundle on that page).

## Adding a locale

1. Copy `public/_locales/en/` to `public/_locales/<code>/` (Chrome locale codes: `de`,
   `pt_BR`, `zh_CN`, ...).
2. Translate each `message`. Keep every placeholder: `$NAME$` names and `$1`..`$9` must stay
   as they are, and the `placeholders` blocks must not change. `$$` is a literal dollar sign.
   `description` fields are notes for translators and need no translation.
3. Keys you do not translate can be deleted: Chrome falls back to `en` (`default_locale`).
4. Run `npm run i18n`. It fails on keys that are not in `en` and on placeholders that differ
   from `en`.
5. Build (`npm run build`), load `.output/chrome-mv3`, and start Chrome with
   `--lang=<code>` to check the result, including the extensions page and the shortcuts page.

## What is not translated

- The brand name "Tabitat" (and "Tabitat New Tab"): `appName` / `appNameNewTab` keep it.
- Keyboard shortcut keys (Chrome formats them per platform).
- Dates, times and numbers use the browser's locale through `Intl`, not messages.
- Content the user typed (workspace names, todos, notes) and page titles.

## `npm run i18n` (scripts/check-i18n.mjs)

Part of `npm run check`. It scans `src/**/*.{ts,tsx,html}` and `wxt.config.ts` (tests and
test helpers are ignored) and fails on:

- **unused keys**: a message nothing references. References are `t`/`plural`/`getMessage`
  calls, `__MSG_key__`, key strings kept in constant maps or arrays (any string literal equal
  to a key that contains an upper-case letter or `_`, such as `"err_busy"` or
  `"exportTitle"`), and declared dynamic families. A plain lower-case key (`"cancel"`) only
  counts through a direct call, because such words also appear as ordinary strings.
- **missing keys**: a call or `__MSG_` reference to a key that is not in `en`.
- **placeholder mismatches**: `$NAME$` without a declared placeholder, a placeholder the message
  never uses, and call sites whose substitutions do not match the `$n` the message uses.
- **dynamic families**: keys built at runtime (`` t(`color_${c}`) ``) must be declared in
  `DYNAMIC_FAMILIES` in the script with a reason; a declared family that no code builds any more
  fails too.
- **other locales**: keys not in `en`, placeholders that differ from `en`.

`node scripts/check-i18n.mjs --json` prints the full result for tooling.
